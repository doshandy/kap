## wcag-semantic
title: 可访问性的起点是语义化，而不是补 ARIA
difficulty: 基础
tags: [a11y, 语义化]

### 题目
为什么说“先用对 HTML 元素，再谈 ARIA”？请举几个典型例子。

### 答案要点
- 语义元素自带角色、键盘行为和可访问树信息
- 用按钮就用 `<button>`，不要拿 `<div>` 模拟点击
- 表单关联 `label`、标题层级、列表结构、表格语义都是基础
- ARIA 主要用于补充原生语义不足，而不是替代原生语义

### 代码示例
```html
<!-- ❌ 反例：div 模拟按钮，丢失键盘可访问性 -->
<div class="btn" onclick="submit()">提交</div>

<!-- ✅ 用原生 button -->
<button type="button" @click="submit">提交</button>

<!-- ✅ 表单：label 关联 input，错误用 aria-describedby -->
<label for="email">邮箱</label>
<input
  id="email"
  v-model="email"
  type="email"
  required
  aria-invalid="true"
  aria-describedby="email-err"
/>
<p id="email-err" class="error">请填写有效邮箱</p>

<!-- ✅ 标题层级：h1→h2→h3 不要跳级 -->
<main>
  <h1>页面标题</h1>
  <section>
    <h2>章节标题</h2>
    <h3>子标题</h3>
  </section>
</main>

<!-- ✅ 图片必须有替代文本（装饰性图片用空 alt） -->
<img src="logo.svg" alt="公司 Logo" />
<img src="bg.svg" alt="" role="presentation" />

<!-- ✅ 列表用 ul/ol/li，表格用 table/th/td/caption -->
<table>
  <caption>2026 销售数据</caption>
  <thead>
    <tr><th scope="col">月份</th><th scope="col">销量</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">1月</th><td>120</td></tr>
  </tbody>
</table>
```

### 延伸
- 很多无障碍问题不是"没加 aria"，而是先天组件语义就错了

## focus-keyboard
title: 键盘导航与焦点管理是前端最常见的无障碍硬指标
difficulty: 进阶
tags: [焦点管理, 键盘]

### 题目
做弹窗、抽屉、下拉菜单时，焦点管理为什么经常决定可访问性成败？

### 答案要点
- 打开弹窗时应把焦点移入，关闭时归还触发元素
- 模态框内要做焦点圈闭，避免 Tab 跑到背景页面
- 键盘操作应支持 Esc 关闭、方向键切换、Enter/Space 激活等

### 代码示例
```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';

const props = defineProps<{ open: boolean }>();
const emit = defineEmits<{ (e: 'close'): void }>();

const dialogRef = ref<HTMLDivElement>();
let lastActive: HTMLElement | null = null;

watch(() => props.open, async (open) => {
  if (open) {
    lastActive = document.activeElement as HTMLElement;
    await nextTick();
    // 1. 焦点移入弹窗第一个可聚焦元素
    const first = dialogRef.value?.querySelector<HTMLElement>(
      'input,button,select,textarea,[tabindex]:not([tabindex="-1"])',
    );
    first?.focus();
  } else {
    // 2. 关闭后焦点归还触发元素
    lastActive?.focus();
  }
});

// 3. 焦点圈闭：Tab/Shift+Tab 不能跳出弹窗
function onKeydown(e: KeyboardEvent) {
  if (!props.open) return;
  if (e.key === 'Escape') return emit('close');
  if (e.key !== 'Tab') return;

  const focusables = dialogRef.value!.querySelectorAll<HTMLElement>(
    'input,button,select,textarea,a[href],[tabindex]:not([tabindex="-1"])',
  );
  const first = focusables[0];
  const last = focusables[focusables.length - 1];

  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }
}

window.addEventListener('keydown', onKeydown);
onUnmounted(() => window.removeEventListener('keydown', onKeydown));
</script>

<template>
  <Teleport to="body">
    <div
      v-if="open"
      ref="dialogRef"
      role="dialog"
      aria-modal="true"
      aria-labelledby="dialog-title"
    >
      <h2 id="dialog-title">确认操作</h2>
      <button @click="$emit('close')" aria-label="关闭对话框">×</button>
      <slot />
    </div>
  </Teleport>
</template>
```

### 延伸
- 焦点顺序混乱不仅影响残障用户，也会显著影响键盘重度用户效率

## aria-live-errors
title: aria-live、错误提示与动态内容更新
difficulty: 进阶
tags: [ARIA, 表单]

### 题目
动态提示、表单报错、加载状态要怎样做，屏幕阅读器才能感知？

### 答案要点
- 对重要动态消息使用 `aria-live` 区域
- 表单错误要和具体字段建立关联，如 `aria-describedby`
- 加载中、成功、失败状态要有可感知文案，而不只是颜色变化

### 代码示例
```vue
<template>
  <!-- 1. 重要状态变更：aria-live="assertive" 立即播报 -->
  <div role="alert" aria-live="assertive">
    <p v-if="error">{{ error }}</p>
  </div>

  <!-- 2. 一般动态信息：aria-live="polite" 等待空闲再播 -->
  <div aria-live="polite" class="sr-only">
    {{ statusMessage }}
  </div>

  <!-- 3. 加载中：aria-busy + 可见文字 -->
  <button :aria-busy="loading" :disabled="loading">
    <span v-if="loading">提交中...</span>
    <span v-else>提交</span>
  </button>

  <!-- 4. 表单错误：aria-describedby 关联 -->
  <label for="pwd">密码</label>
  <input
    id="pwd"
    type="password"
    :aria-invalid="!!errors.pwd"
    aria-describedby="pwd-help pwd-err"
  />
  <p id="pwd-help">至少 8 位，包含字母与数字</p>
  <p id="pwd-err" v-if="errors.pwd" class="error">{{ errors.pwd }}</p>
</template>

<style>
/* 屏幕阅读器可见但视觉隐藏 */
.sr-only {
  position: absolute;
  width: 1px; height: 1px;
  padding: 0; margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```

### 延伸
- 可访问性不是只给"最终结果"，而是让交互过程全程可理解

## reduced-motion-contrast
title: 对比度、高对比模式与 reduced motion
difficulty: 基础
tags: [视觉可访问性, 动效]

### 题目
为什么“看起来高级”的设计，可能恰恰会损害可访问性？

### 答案要点
- 对比度不足会导致正文、按钮和状态信息难以辨认
- 不能只靠颜色表达状态，需要图标、文本或结构辅助
- 对大动效、滚动动画要尊重 `prefers-reduced-motion`

### 代码示例
```css
/* 1. 对比度：正文至少 4.5:1，大字至少 3:1（WCAG AA） */
:root {
  --text: #111;       /* 与白底对比度 ~17:1 */
  --text-muted: #666; /* 与白底对比度 ~5.7:1 */
  --link: #0958d9;    /* 与白底对比度 ~4.6:1 */
}

/* 2. 不仅靠颜色：状态用颜色 + 图标 + 文字 */
.status-error::before { content: '❌ '; }
.status-success::before { content: '✅ '; }

/* 3. 高对比度模式 */
@media (prefers-contrast: more) {
  :root {
    --text: #000;
    --bg: #fff;
    --border: #000;
  }
  button { border: 2px solid currentColor; }
}

/* 4. 减少动效（眩晕症友好） */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 5. focus-visible：仅键盘导航显示焦点环 */
button:focus { outline: none; }
button:focus-visible {
  outline: 3px solid #0ea5e9;
  outline-offset: 2px;
}
```

```ts
// JS 端检测用户偏好
const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduceMotion) playEntryAnimation();
```

### 延伸
- 无障碍不是限制设计，而是让设计在更多人群中可用

## vue-i18n-intl
title: Vue I18n、Intl API 与多语言资源组织
difficulty: 进阶
tags: [i18n, Intl]

### 题目
国际化为什么不只是“把文案抽出去”？日期、数字、复数规则又该如何处理？

### 答案要点
- 文案资源需要命名规范、按页面/领域拆分、支持懒加载
- 日期、数字、货币、相对时间应尽量使用 `Intl` 系列 API
- 复数规则、占位顺序、语序变化不能硬编码中文思维

### 代码示例
```ts
// 1. Vue I18n 9：按语言/页面拆分 + 懒加载
import { createI18n } from 'vue-i18n';

const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en',
  messages: {},
});

async function loadLocale(locale: string) {
  const messages = await import(`@/locales/${locale}.json`);
  i18n.global.setLocaleMessage(locale, messages.default);
  i18n.global.locale.value = locale as any;
  document.documentElement.lang = locale;
}
```

```vue
<template>
  <!-- 2. 模板里使用 -->
  <h1>{{ $t('dashboard.title') }}</h1>

  <!-- 3. 复数（注意不同语言的规则不同）-->
  <p>{{ $t('cart.items', { count }, count) }}</p>

  <!-- 4. 占位符顺序由翻译者控制 -->
  <p>{{ $t('greeting', { name: user.name, date }) }}</p>
</template>
```

```json
// locales/zh-CN.json
{
  "dashboard": { "title": "仪表盘" },
  "cart": {
    "items": "购物车有 {count} 件商品 | 购物车有 {count} 件商品"
  },
  "greeting": "你好 {name}，今天是 {date}"
}

// locales/en.json
{
  "cart": {
    "items": "no items | one item | {count} items"
  },
  "greeting": "Hello {name}, today is {date}"
}
```

```ts
// 5. Intl API：日期/数字/货币（无需第三方库）
new Intl.DateTimeFormat('zh-CN', { dateStyle: 'long' }).format(new Date());
// '2026年5月6日'

new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(1234.5);
// '$1,234.50'

new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' }).format(-3, 'day');
// '3天前'

new Intl.PluralRules('en').select(1);   // 'one'
new Intl.PluralRules('en').select(2);   // 'other'

// 列表格式化
new Intl.ListFormat('zh-CN', { type: 'conjunction' }).format(['苹果', '香蕉', '橘子']);
// '苹果、香蕉和橘子'
```

### 延伸
- i18n 的难点常在工程组织和内容流程，不只是技术 API

## rtl-ssr
title: RTL、逻辑属性与 SSR 下的国际化一致性
difficulty: 进阶
tags: [RTL, SSR]

### 题目
为什么国际化项目应尽量使用逻辑属性而不是 left/right？SSR 时语言切换又有哪些额外问题？

### 答案要点
- RTL 语言下布局方向会反转，`margin-inline-start`、`padding-inline-end` 等逻辑属性更稳
- SSR 要保证服务端和客户端语言环境一致，否则会出现 hydration mismatch
- 字体回退、行高、断词策略在不同语言中也要重新审视

### 代码示例
```css
/* ✅ 用逻辑属性，自动适配 LTR/RTL */
.card {
  margin-inline-start: 16px;   /* LTR=margin-left, RTL=margin-right */
  margin-inline-end: 16px;
  padding-inline: 24px;
  border-inline-start: 2px solid;
  text-align: start;            /* 替代 left/right */
}

/* ✅ 仅在 RTL 下生效的样式 */
[dir='rtl'] .icon-arrow {
  transform: scaleX(-1);        /* 箭头镜像 */
}

/* ❌ 反例：硬编码方向 */
.bad {
  margin-left: 16px;
  text-align: left;
}
```

```ts
// HTML 根节点设置 lang + dir，浏览器和 CSS 都会响应
function applyLocale(locale: string) {
  const rtlLocales = ['ar', 'he', 'fa', 'ur'];
  const isRtl = rtlLocales.some(l => locale.startsWith(l));
  document.documentElement.lang = locale;
  document.documentElement.dir = isRtl ? 'rtl' : 'ltr';
}
```

```ts
// SSR：从请求头/cookie 检测语言，确保首屏一致
// Nuxt server middleware
export default defineEventHandler(event => {
  const accept = getHeader(event, 'accept-language') || '';
  const cookieLang = getCookie(event, 'lang');
  const lang = cookieLang || accept.split(',')[0].split('-')[0] || 'en';

  // 注入到 SSR context，让 Vue I18n 在服务端用同一份消息
  event.context.lang = lang;
});

// Vue 应用入口
const lang = useNuxtApp().ssrContext?.event.context.lang ?? 'en';
i18n.global.locale.value = lang;
```

### 延伸
- 只支持英文和中文时感觉不到问题，多语言一扩张，布局假设就会暴露
