## wcag-semantic
title: 可访问性的起点是语义化，而不是补 ARIA
difficulty: 基础
tags: [a11y, 语义化]

### 题目
为什么说“先用对 HTML 元素，再谈 ARIA”？请举几个典型例子。

### 答案要点
- 语义元素自带角色、键盘行为和可访问树信息
- 用按钮就用 `<button>`，不要拿 `<div>` 模拟点击
- 表单关联 `label`、标题层级、列表结构、表格语义都是基础
- ARIA 主要用于补充原生语义不足，而不是替代原生语义

### 代码示例
```html
<!-- ❌ 反例：div 模拟按钮，丢失键盘可访问性 -->
<div class="btn" onclick="submit()">提交</div>

<!-- ✅ 用原生 button -->
<button type="button" @click="submit">提交</button>

<!-- ✅ 表单：label 关联 input，错误用 aria-describedby -->
<label for="email">邮箱</label>
<input
  id="email"
  v-model="email"
  type="email"
  required
  aria-invalid="true"
  aria-describedby="email-err"
/>
<p id="email-err" class="error">请填写有效邮箱</p>

<!-- ✅ 标题层级：h1→h2→h3 不要跳级 -->
<main>
  <h1>页面标题</h1>
  <section>
    <h2>章节标题</h2>
    <h3>子标题</h3>
  </section>
</main>

<!-- ✅ 图片必须有替代文本（装饰性图片用空 alt） -->
<img src="logo.svg" alt="公司 Logo" />
<img src="bg.svg" alt="" role="presentation" />

<!-- ✅ 列表用 ul/ol/li，表格用 table/th/td/caption -->
<table>
  <caption>2026 销售数据</caption>
  <thead>
    <tr><th scope="col">月份</th><th scope="col">销量</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">1月</th><td>120</td></tr>
  </tbody>
</table>
```

### 延伸
- 很多无障碍问题不是"没加 aria"，而是先天组件语义就错了

## focus-keyboard
title: 键盘导航与焦点管理是前端最常见的无障碍硬指标
difficulty: 进阶
tags: [焦点管理, 键盘]

### 题目
做弹窗、抽屉、下拉菜单时，焦点管理为什么经常决定可访问性成败？

### 答案要点
- 打开弹窗时应把焦点移入，关闭时归还触发元素
- 模态框内要做焦点圈闭，避免 Tab 跑到背景页面
- 键盘操作应支持 Esc 关闭、方向键切换、Enter/Space 激活等

### 代码示例
```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';

const props = defineProps<{ open: boolean }>();
const emit = defineEmits<{ (e: 'close'): void }>();

const dialogRef = ref<HTMLDivElement>();
let lastActive: HTMLElement | null = null;

watch(() => props.open, async (open) => {
  if (open) {
    lastActive = document.activeElement as HTMLElement;
    await nextTick();
    // 1. 焦点移入弹窗第一个可聚焦元素
    const first = dialogRef.value?.querySelector<HTMLElement>(
      'input,button,select,textarea,[tabindex]:not([tabindex="-1"])',
    );
    first?.focus();
  } else {
    // 2. 关闭后焦点归还触发元素
    lastActive?.focus();
  }
});

// 3. 焦点圈闭：Tab/Shift+Tab 不能跳出弹窗
function onKeydown(e: KeyboardEvent) {
  if (!props.open) return;
  if (e.key === 'Escape') return emit('close');
  if (e.key !== 'Tab') return;

  const focusables = dialogRef.value!.querySelectorAll<HTMLElement>(
    'input,button,select,textarea,a[href],[tabindex]:not([tabindex="-1"])',
  );
  const first = focusables[0];
  const last = focusables[focusables.length - 1];

  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }
}

window.addEventListener('keydown', onKeydown);
onUnmounted(() => window.removeEventListener('keydown', onKeydown));
</script>

<template>
  <Teleport to="body">
    <div
      v-if="open"
      ref="dialogRef"
      role="dialog"
      aria-modal="true"
      aria-labelledby="dialog-title"
    >
      <h2 id="dialog-title">确认操作</h2>
      <button @click="$emit('close')" aria-label="关闭对话框">×</button>
      <slot />
    </div>
  </Teleport>
</template>
```

### 延伸
- 焦点顺序混乱不仅影响残障用户，也会显著影响键盘重度用户效率

## aria-live-errors
title: aria-live、错误提示与动态内容更新
difficulty: 进阶
tags: [ARIA, 表单]

### 题目
动态提示、表单报错、加载状态要怎样做，屏幕阅读器才能感知？

### 答案要点
- 对重要动态消息使用 `aria-live` 区域
- 表单错误要和具体字段建立关联，如 `aria-describedby`
- 加载中、成功、失败状态要有可感知文案，而不只是颜色变化

### 代码示例
```vue
<template>
  <!-- 1. 重要状态变更：aria-live="assertive" 立即播报 -->
  <div role="alert" aria-live="assertive">
    <p v-if="error">{{ error }}</p>
  </div>

  <!-- 2. 一般动态信息：aria-live="polite" 等待空闲再播 -->
  <div aria-live="polite" class="sr-only">
    {{ statusMessage }}
  </div>

  <!-- 3. 加载中：aria-busy + 可见文字 -->
  <button :aria-busy="loading" :disabled="loading">
    <span v-if="loading">提交中...</span>
    <span v-else>提交</span>
  </button>

  <!-- 4. 表单错误：aria-describedby 关联 -->
  <label for="pwd">密码</label>
  <input
    id="pwd"
    type="password"
    :aria-invalid="!!errors.pwd"
    aria-describedby="pwd-help pwd-err"
  />
  <p id="pwd-help">至少 8 位，包含字母与数字</p>
  <p id="pwd-err" v-if="errors.pwd" class="error">{{ errors.pwd }}</p>
</template>

<style>
/* 屏幕阅读器可见但视觉隐藏 */
.sr-only {
  position: absolute;
  width: 1px; height: 1px;
  padding: 0; margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```

### 延伸
- 可访问性不是只给"最终结果"，而是让交互过程全程可理解

## reduced-motion-contrast
title: 对比度、高对比模式与 reduced motion
difficulty: 基础
tags: [视觉可访问性, 动效]

### 题目
为什么“看起来高级”的设计，可能恰恰会损害可访问性？

### 答案要点
- 对比度不足会导致正文、按钮和状态信息难以辨认
- 不能只靠颜色表达状态，需要图标、文本或结构辅助
- 对大动效、滚动动画要尊重 `prefers-reduced-motion`

### 代码示例
```css
/* 1. 对比度：正文至少 4.5:1，大字至少 3:1（WCAG AA） */
:root {
  --text: #111;       /* 与白底对比度 ~17:1 */
  --text-muted: #666; /* 与白底对比度 ~5.7:1 */
  --link: #0958d9;    /* 与白底对比度 ~4.6:1 */
}

/* 2. 不仅靠颜色：状态用颜色 + 图标 + 文字 */
.status-error::before { content: '❌ '; }
.status-success::before { content: '✅ '; }

/* 3. 高对比度模式 */
@media (prefers-contrast: more) {
  :root {
    --text: #000;
    --bg: #fff;
    --border: #000;
  }
  button { border: 2px solid currentColor; }
}

/* 4. 减少动效（眩晕症友好） */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 5. focus-visible：仅键盘导航显示焦点环 */
button:focus { outline: none; }
button:focus-visible {
  outline: 3px solid #0ea5e9;
  outline-offset: 2px;
}
```

```ts
// JS 端检测用户偏好
const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduceMotion) playEntryAnimation();
```

### 延伸
- 无障碍不是限制设计，而是让设计在更多人群中可用

## vue-i18n-intl
title: Vue I18n、Intl API 与多语言资源组织
difficulty: 进阶
tags: [i18n, Intl]

### 题目
国际化为什么不只是“把文案抽出去”？日期、数字、复数规则又该如何处理？

### 答案要点
- 文案资源需要命名规范、按页面/领域拆分、支持懒加载
- 日期、数字、货币、相对时间应尽量使用 `Intl` 系列 API
- 复数规则、占位顺序、语序变化不能硬编码中文思维

### 代码示例
```ts
// 1. Vue I18n 9：按语言/页面拆分 + 懒加载
import { createI18n } from 'vue-i18n';

const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en',
  messages: {},
});

async function loadLocale(locale: string) {
  const messages = await import(`@/locales/${locale}.json`);
  i18n.global.setLocaleMessage(locale, messages.default);
  i18n.global.locale.value = locale as any;
  document.documentElement.lang = locale;
}
```

```vue
<template>
  <!-- 2. 模板里使用 -->
  <h1>{{ $t('dashboard.title') }}</h1>

  <!-- 3. 复数（注意不同语言的规则不同）-->
  <p>{{ $t('cart.items', { count }, count) }}</p>

  <!-- 4. 占位符顺序由翻译者控制 -->
  <p>{{ $t('greeting', { name: user.name, date }) }}</p>
</template>
```

```json
// locales/zh-CN.json
{
  "dashboard": { "title": "仪表盘" },
  "cart": {
    "items": "购物车有 {count} 件商品 | 购物车有 {count} 件商品"
  },
  "greeting": "你好 {name}，今天是 {date}"
}

// locales/en.json
{
  "cart": {
    "items": "no items | one item | {count} items"
  },
  "greeting": "Hello {name}, today is {date}"
}
```

```ts
// 5. Intl API：日期/数字/货币（无需第三方库）
new Intl.DateTimeFormat('zh-CN', { dateStyle: 'long' }).format(new Date());
// '2026年5月6日'

new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(1234.5);
// '$1,234.50'

new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' }).format(-3, 'day');
// '3天前'

new Intl.PluralRules('en').select(1);   // 'one'
new Intl.PluralRules('en').select(2);   // 'other'

// 列表格式化
new Intl.ListFormat('zh-CN', { type: 'conjunction' }).format(['苹果', '香蕉', '橘子']);
// '苹果、香蕉和橘子'
```

### 延伸
- i18n 的难点常在工程组织和内容流程，不只是技术 API

## rtl-ssr
title: RTL、逻辑属性与 SSR 下的国际化一致性
difficulty: 进阶
tags: [RTL, SSR]

### 题目
为什么国际化项目应尽量使用逻辑属性而不是 left/right？SSR 时语言切换又有哪些额外问题？

### 答案要点
- RTL 语言下布局方向会反转，`margin-inline-start`、`padding-inline-end` 等逻辑属性更稳
- SSR 要保证服务端和客户端语言环境一致，否则会出现 hydration mismatch
- 字体回退、行高、断词策略在不同语言中也要重新审视

### 代码示例
```css
/* ✅ 用逻辑属性，自动适配 LTR/RTL */
.card {
  margin-inline-start: 16px;   /* LTR=margin-left, RTL=margin-right */
  margin-inline-end: 16px;
  padding-inline: 24px;
  border-inline-start: 2px solid;
  text-align: start;            /* 替代 left/right */
}

/* ✅ 仅在 RTL 下生效的样式 */
[dir='rtl'] .icon-arrow {
  transform: scaleX(-1);        /* 箭头镜像 */
}

/* ❌ 反例：硬编码方向 */
.bad {
  margin-left: 16px;
  text-align: left;
}
```

```ts
// HTML 根节点设置 lang + dir，浏览器和 CSS 都会响应
function applyLocale(locale: string) {
  const rtlLocales = ['ar', 'he', 'fa', 'ur'];
  const isRtl = rtlLocales.some(l => locale.startsWith(l));
  document.documentElement.lang = locale;
  document.documentElement.dir = isRtl ? 'rtl' : 'ltr';
}
```

```ts
// SSR：从请求头/cookie 检测语言，确保首屏一致
// Nuxt server middleware
export default defineEventHandler(event => {
  const accept = getHeader(event, 'accept-language') || '';
  const cookieLang = getCookie(event, 'lang');
  const lang = cookieLang || accept.split(',')[0].split('-')[0] || 'en';

  // 注入到 SSR context，让 Vue I18n 在服务端用同一份消息
  event.context.lang = lang;
});

// Vue 应用入口
const lang = useNuxtApp().ssrContext?.event.context.lang ?? 'en';
i18n.global.locale.value = lang;
```

### 延伸
- 只支持英文和中文时感觉不到问题，多语言一扩张，布局假设就会暴露

## screen-reader-testing
title: 屏幕阅读器调试与回归
difficulty: 进阶
tags: [屏幕阅读器, 测试]

### 题目
怎么在开发期就保证组件对屏幕阅读器友好？有哪些工具和习惯？

### 答案要点
- 系统：macOS VoiceOver（Cmd+F5）、Windows NVDA / JAWS、iOS VoiceOver、Android TalkBack
- 单测：`@testing-library/jest-dom` + `axe-core`（如 `@axe-core/playwright`）跑 a11y 规则
- 浏览器：Chrome DevTools 的 Accessibility Tree 面板查看实际朗读结构
- 常见问题：图标按钮缺 aria-label、表单控件缺 label、动态内容缺 aria-live
- 焦点：Modal / Drawer 打开时 focus trap，关闭时焦点回到触发元素
- 自动化：CI 跑 axe，把违反 WCAG 2.1 AA 的规则标红 / 阻塞合并

### 代码示例
```ts
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

test('首页无可访问性问题', async ({ page }) => {
  await page.goto('/');
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa'])
    .analyze();
  expect(results.violations).toEqual([]);
});
```

```vue
<button :aria-label="收藏 ? '取消收藏' : '收藏'" :aria-pressed="收藏" @click="toggleStar">
  <StarIcon :filled="收藏" />
</button>

<div role="status" aria-live="polite" class="sr-only">
  {{ status === 'saving' ? '正在保存…' : status === 'saved' ? '已保存' : '' }}
</div>
```

### 延伸
- 自动化只能覆盖 30%~40% 的 a11y 问题，关键流程必须人工跑一遍屏幕阅读器
- 设计稿评审就引入 a11y check list，比上线后修改成本低 10 倍

## intl-format-deep
title: Intl 标准 API 在国际化中的实际应用
difficulty: 进阶
tags: [Intl, 国际化]

### 题目
浏览器内置的 `Intl.*` 在 i18n 中能解决哪些问题？哪些坑要注意？

### 答案要点
- `Intl.NumberFormat`：千分位、货币、紧凑（1.2K）、单位（米/秒）
- `Intl.DateTimeFormat`：根据 locale 输出日期，自动处理农历 / 阿拉伯日历
- `Intl.RelativeTimeFormat`："3 小时前"，比手写数组干净
- `Intl.PluralRules`：根据数字给出复数类（zero / one / few / many / other），写英文复数必备
- `Intl.ListFormat`：把数组转成自然语言列表（"A、B 和 C"）
- `Intl.Segmenter`：按字 / 词 / 句切分，取代旧的正则切词
- 注意：旧浏览器对 locale 数据支持不全，必要时 polyfill `@formatjs/*`

### 代码示例
```ts
const cny = new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' });
console.log(cny.format(12345.6)); // ¥12,345.60

const rtf = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' });
console.log(rtf.format(-1, 'day')); // 昨天
console.log(rtf.format(-3, 'day')); // 3天前

const pr = new Intl.PluralRules('en');
function pluralize(n: number) {
  const rule = pr.select(n);
  return { one: 'item', other: 'items' }[rule] ?? 'items';
}

const list = new Intl.ListFormat('zh-CN', { type: 'conjunction' });
console.log(list.format(['前端', '后端', '运维'])); // 前端、后端和运维

const seg = new Intl.Segmenter('zh-CN', { granularity: 'word' });
for (const s of seg.segment('我爱前端开发')) console.log(s.segment, s.isWordLike);
```

### 延伸
- 复杂消息（嵌套占位符 / 选择器）继续用 ICU MessageFormat（@formatjs/intl-messageformat）
- 服务端要预先按 Accept-Language 选择 locale，避免客户端首屏闪烁

## aria-roles-states
title: ARIA 的 role / state / property 是什么，什么时候该用
difficulty: 进阶
tags: [a11y, ARIA]

### 一句话
能用语义 HTML（`<button>` `<nav>` `<main>`）就别用 ARIA；ARIA 是给"自定义组件"补语义的，第一原则是 **No ARIA is better than Bad ARIA**。

### 题目
ARIA 的 role / aria-* 属性分别解决什么问题？典型组件（Tabs / Modal / Combobox）需要哪些标注？

### 答案要点
- `role`：告诉辅助技术"这是一个什么角色"（button / dialog / tab / menu / alert）
- `aria-label / aria-labelledby / aria-describedby`：补充无法从可见文本推断的标签
- `aria-expanded / aria-selected / aria-checked / aria-pressed`：状态
- `aria-controls / aria-owns`：建立逻辑上的归属关系
- `aria-live="polite|assertive"`：告诉读屏器"这块内容会动态更新，请播报"
- 第一原则："No ARIA is better than Bad ARIA"——能用 `<button>` `<dialog>` 就别用 div + role
- 典型组件：
  - Modal：`role="dialog"` + `aria-modal="true"` + 焦点陷阱 + `aria-labelledby`
  - Tabs：tablist > tab[aria-selected] + tabpanel[aria-labelledby]
  - Combobox：`role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`

### 代码示例
```html
<button
  type="button"
  aria-expanded="false"
  aria-controls="menu1"
>
  菜单
</button>
<ul id="menu1" role="menu" hidden>
  <li role="menuitem">选项 1</li>
</ul>

<div role="dialog" aria-modal="true" aria-labelledby="title1">
  <h2 id="title1">确认删除？</h2>
</div>
```

### 延伸
- Chrome DevTools 的 Accessibility 面板可查看节点的可访问性树
- WAI-ARIA Authoring Practices 给出了所有常见组件的 ARIA 模式参考
- 测试：Axe / Lighthouse / VoiceOver / NVDA

## i18n-locale-formatter
title: 国际化中数字、日期、复数怎么处理才对
difficulty: 进阶
tags: [i18n, Intl]

### 一句话
别再自己拼字符串。用浏览器内建 `Intl.NumberFormat / DateTimeFormat / RelativeTimeFormat / PluralRules`，零依赖处理 200+ 语言。

### 题目
请展示 `Intl` API 在数字、日期、相对时间和复数处理中的用法。

### 答案要点
- `Intl.NumberFormat(locale, { style: 'currency', currency: 'CNY' })` —— 货币、千分位、单位
- `Intl.DateTimeFormat(locale, options)` —— 日期/时间格式（含中文长格式、农历可选）
- `Intl.RelativeTimeFormat(locale)` —— "3 天前" "in 5 minutes"
- `Intl.PluralRules(locale)` —— 处理复数变体（英语 one/other，俄语 one/few/many/other）
- `Intl.ListFormat / Segmenter / Collator` —— 列表拼接、分词、排序
- 文案管理：`vue-i18n` / `react-intl` / `formatjs` 用 ICU MessageFormat 表达复数与变量

### 代码示例
```js
new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(1234567.89);

new Intl.DateTimeFormat('zh-CN', { dateStyle: 'long', timeStyle: 'short' }).format(new Date());

const rtf = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' });
rtf.format(-3, 'day'); // "3 天前"

const pr = new Intl.PluralRules('en');
pr.select(1); // "one"
pr.select(5); // "other"

const seg = new Intl.Segmenter('zh', { granularity: 'word' });
[...seg.segment('我爱前端')].map(s => s.segment);
```

### 延伸
- 时区处理首选 `Intl.DateTimeFormat` 的 `timeZone` 选项 + Temporal（提案中）
- 真实业务中翻译文件优先 ICU MessageFormat，避免拼接 bug
- RTL（阿拉伯语）需要 `dir="rtl"` 与 `:dir(rtl)` 选择器配合


## form-accessibility
title: 表单 a11y 完整 checklist
difficulty: 进阶
tags: [无障碍, 表单, 高频]

### 一句话
**label 必须显式关联 input**（`<label for>` 或包裹）；**错误用 aria-invalid + aria-describedby** 关联到错误文案；**必填用 aria-required**；提交后焦点回到第一个错误项；屏幕阅读器要能完整朗读"标签 + 当前值 + 错误"。

### 题目
做一个登录表单 / 注册表单怎么保证无障碍？提交校验失败时怎么处理才友好？

### 答案要点
- **基础语义**
  - 用原生 `<form>` `<input>` `<button>`，不要 `<div onclick>` 伪装
  - 每个 input 一个明确的 label，要么 `<label for="email">` 要么把 input 包在 label 里
  - placeholder 不能替代 label（屏幕阅读器读不到 / 用户开始输入就看不见）
- **必填 / 类型 / 自动填充**
  - 必填：`required` + `aria-required="true"`
  - 类型语义化：`type="email" / tel / url / password`，移动端弹合适键盘
  - autocomplete：`autocomplete="email" / current-password / new-password / one-time-code`，省事+安全
- **错误处理**
  - 出错的 input 加 `aria-invalid="true"`
  - 错误文案用唯一 id，input 的 `aria-describedby` 指过去
  - 错误文案也用 `role="alert"` 或在 live region 里更新（屏幕阅读器立刻读出）
  - 提交后用 JS 把焦点移到第一个错误项（用户不用 Tab 找）
- **不仅靠颜色**
  - 红框 + 图标 + 文字三重提示（色盲也能识别）
  - 对比度 ≥ 4.5:1
- **键盘**
  - Tab 顺序符合视觉顺序
  - Enter 提交（除非显式禁用）
  - Esc 关闭弹窗 / 清空（视产品而定）
- **加载与禁用**
  - 提交中：button disabled + 显示 spinner + `aria-busy="true"`
  - 不要禁用整个 form 让用户以为卡死，加文案"提交中..."

### 代码示例
```html
<form @submit.prevent="onSubmit" novalidate>
  <div class="field">
    <label for="email">邮箱</label>
    <input
      id="email"
      v-model="form.email"
      type="email"
      autocomplete="email"
      required
      aria-required="true"
      :aria-invalid="errors.email ? 'true' : 'false'"
      :aria-describedby="errors.email ? 'email-err' : undefined"
    />
    <p v-if="errors.email" id="email-err" class="err" role="alert">{{ errors.email }}</p>
  </div>

  <button type="submit" :disabled="submitting" :aria-busy="submitting">
    {{ submitting ? '提交中…' : '登录' }}
  </button>
</form>

<script setup>
async function onSubmit() {
  errors.value = validate(form.value);
  await nextTick();
  const first = document.querySelector('[aria-invalid="true"]');
  (first as HTMLElement | null)?.focus();
}
</script>

<style>
.field input[aria-invalid="true"] {
  border-color: #d4380d;
  outline-color: #d4380d;
}
.err::before { content: '⚠ '; }
</style>
```

### 延伸
- 自动填充友好：`name` 用标准词（given-name / family-name / postal-code）
- 二次确认密码用 `autocomplete="new-password"` 让浏览器不带旧密码
