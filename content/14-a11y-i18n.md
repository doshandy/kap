## wcag-semantic

title: 可访问性的起点是语义化，而不是补 ARIA
followups: [wcag-semantic-followup-1, wcag-semantic-followup-2, wcag-semantic-followup-3]
links: [04-css/native-popover-dialog-anchor, a11y-quick-wins-basic, aria-roles-states]
difficulty: 基础
tags: [a11y, 语义化]

### 一句话

这题的高分关键是把 a11y 讲成可执行方案：前提清晰、步骤可落地、验收可验证。

### 题目

为什么说“先用对 HTML 元素，再谈 ARIA”？请举几个典型例子。

### 答案要点

- 语义元素自带角色、键盘行为和可访问树信息
- 用按钮就用 ，不要拿 模拟点击
- 表单关联 label、标题层级、列表结构、表格语义都是基础
- ARIA 主要用于补充原生语义不足，而不是替代原生语义

#### 工程化补充

- 场景前提：回答 可访问性的起点是语义化，而不是补 ARIA 时先锁定 a11y 的边界条件，避免把经验结论当成通用规则。
- 实施步骤：先说触发条件，再解释机制，再给反例，避免把“结果”当成“原因”，并且动作要能被他人复现：步骤清晰、信号可观测、异常可回退。
- 失败风险：常见风险是只给理想路径，忽略 a11y 的失败分支与恢复动作。
- 验收信号：验收至少包含围绕 a11y 的可复现用例、线上监控指标和回退演练记录。

### 代码示例

```html
<!-- ❌ 反例：div 模拟按钮，丢失键盘可访问性 -->
<div class="btn" onclick="submit()">提交</div>

<!-- ✅ 用原生 button -->
<button type="button" @click="submit">提交</button>

<!-- ✅ 表单：label 关联 input，错误用 aria-describedby -->
<label for="email">邮箱</label>
<input
  id="email"
  v-model="email"
  type="email"
  required
  aria-invalid="true"
  aria-describedby="email-err"
/>
<p id="email-err" class="error">请填写有效邮箱</p>

<!-- ✅ 标题层级：h1→h2→h3 不要跳级 -->
<main>
  <h1>页面标题</h1>
  <section>
    <h2>章节标题</h2>
    <h3>子标题</h3>
  </section>
</main>

<!-- ✅ 图片必须有替代文本（装饰性图片用空 alt） -->
<img src="logo.svg" alt="公司 Logo" />
<img src="bg.svg" alt="" role="presentation" />

<!-- ✅ 列表用 ul/ol/li，表格用 table/th/td/caption -->
<table>
  <caption>
    2026 销售数据
  </caption>
  <thead>
    <tr>
      <th scope="col">月份</th>
      <th scope="col">销量</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">1月</th>
      <td>120</td>
    </tr>
  </tbody>
</table>
```

### 常见误区

- 回答「可访问性的起点是语义化，而不是补 ARIA」时不要停在定义层，要补充适用条件、失效边界和验证方式。
- 如果没有补充输入边界、失败路径和替代方案，答案会停留在“知道概念”的层面。

### 延伸

## focus-keyboard

title: 键盘导航与焦点管理是前端最常见的无障碍硬指标

### 一句话

讲「键盘导航与焦点管理是前端最常见的无障碍硬指标」时要把结论、动作、风险、验收四段说全，才算可落地答案。

### 题目

做弹窗、抽屉、下拉菜单时，焦点管理为什么经常决定可访问性成败？

### 答案要点

- 打开弹窗时应把焦点移入到首个可交互元素，关闭时归还触发它的按钮
- 模态框内要做焦点圈闭（focus trap），避免 Tab 跑到背景页面
- 键盘操作应支持 Esc 关闭、方向键切换、Enter/Space 激活、Tab 顺序合理
- 隐藏元素用 inert 或 aria-hidden="true"，避免读屏器读到背景内容

#### 工程化补充

- 场景前提：回答 键盘导航与焦点管理是前端最常见的无障碍硬指标 时先锁定 焦点管理 的边界条件，避免把经验结论当成通用规则。
- 实施步骤：先说触发条件，再解释机制，再给反例，避免把“结果”当成“原因”，并且动作安排要覆盖主路径和异常路径，确保上线后可追踪可纠偏。
- 失败风险：常见风险是只给理想路径，忽略 焦点管理 的失败分支与恢复动作。
- 验收信号：验收至少包含围绕 焦点管理 的可复现用例、线上监控指标和回退演练记录。

### 代码示例

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';

const props = defineProps<{ open: boolean }>();
const emit = defineEmits<{ (e: 'close'): void }>();

const dialogRef = ref<HTMLDivElement>();
let lastActive: HTMLElement | null = null;

watch(
  () => props.open,
  async (open) => {
    if (open) {
      lastActive = document.activeElement as HTMLElement;
      await nextTick();
      // 1. 焦点移入弹窗第一个可聚焦元素
      const first = dialogRef.value?.querySelector<HTMLElement>(
        'input,button,select,textarea,[tabindex]:not([tabindex="-1"])',
      );
      first?.focus();
    } else {
      // 2. 关闭后焦点归还触发元素
      lastActive?.focus();
    }
  },
);

// 3. 焦点圈闭：Tab/Shift+Tab 不能跳出弹窗
function onKeydown(e: KeyboardEvent) {
  if (!props.open) return;
  if (e.key === 'Escape') return emit('close');
  if (e.key !== 'Tab') return;

  const focusables = dialogRef.value!.querySelectorAll<HTMLElement>(
    'input,button,select,textarea,a[href],[tabindex]:not([tabindex="-1"])',
  );
  const first = focusables[0];
  const last = focusables[focusables.length - 1];

  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }
}

window.addEventListener('keydown', onKeydown);
onUnmounted(() => window.removeEventListener('keydown', onKeydown));
</script>

<template>
  <Teleport to="body">
    <div v-if="open" ref="dialogRef" role="dialog" aria-modal="true" aria-labelledby="dialog-title">
      <h2 id="dialog-title">确认操作</h2>
      <button @click="$emit('close')" aria-label="关闭对话框">×</button>
      <slot />
    </div>
  </Teleport>
</template>
```

## aria-live-errors

title: aria-live、错误提示与动态内容更新
followups: [aria-live-errors-followup-1, aria-live-errors-followup-2, aria-live-errors-followup-3]
difficulty: 进阶
tags: [ARIA, 表单]

### 一句话

这题的高分关键是把 ARIA 讲成可执行方案：前提清晰、步骤可落地、验收可验证。

### 题目

动态提示、表单报错、加载状态要怎样做，屏幕阅读器才能感知？

### 答案要点

- 对重要动态消息使用 aria-live 区域
- 表单错误要和具体字段建立关联，如 aria-describedby
- 加载中、成功、失败状态要有可感知文案，而不只是颜色变化
- 面试中不要只停留在「aria-live、错误提示与动态内容更新」的定义，还要解释为什么需要它、它解决了哪类问题，以及在哪些约束下会失效。

#### 工程化补充

- 场景前提：回答 aria-live、错误提示与动态内容更新 时先锁定 ARIA 的边界条件，避免把经验结论当成通用规则。
- 实施步骤：按“先复现现状 -> 再最小改动实现 -> 最后补回归”推进，确保每一步都可回退，并且动作要能被他人复现：步骤清晰、信号可观测、异常可回退。
- 失败风险：常见风险是只给理想路径，忽略 ARIA 的失败分支与恢复动作。
- 验收信号：验收至少包含围绕 ARIA 的可复现用例、线上监控指标和回退演练记录。

### 代码示例

```vue
<template>
  <!-- 1. 重要状态变更：aria-live="assertive" 立即播报 -->
  <div role="alert" aria-live="assertive">
    <p v-if="error">{{ error }}</p>
  </div>

  <!-- 2. 一般动态信息：aria-live="polite" 等待空闲再播 -->
  <div aria-live="polite" class="sr-only">
    {{ statusMessage }}
  </div>

  <!-- 3. 加载中：aria-busy + 可见文字 -->
  <button :aria-busy="loading" :disabled="loading">
    <span v-if="loading">提交中...</span>
    <span v-else>提交</span>
  </button>

  <!-- 4. 表单错误：aria-describedby 关联 -->
  <label for="pwd">密码</label>
  <input
    id="pwd"
    type="password"
    :aria-invalid="!!errors.pwd"
    aria-describedby="pwd-help pwd-err"
  />
  <p id="pwd-help">至少 8 位，包含字母与数字</p>
  <p id="pwd-err" v-if="errors.pwd" class="error">{{ errors.pwd }}</p>
</template>

<style>
/* 屏幕阅读器可见但视觉隐藏 */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```

## reduced-motion-contrast

title: 对比度、高对比模式与 reduced motion
followups: [reduced-motion-contrast-followup-1, reduced-motion-contrast-followup-2, reduced-motion-contrast-followup-3]
difficulty: 基础
tags: [视觉可访问性, 动效]

### 一句话

讲「对比度、高对比模式与 reduced motion」时要把结论、动作、风险、验收四段说全，才算可落地答案。

### 题目

为什么“看起来高级”的设计，可能恰恰会损害可访问性？

### 答案要点

- 对比度不足会导致正文、按钮和状态信息难以辨认
- 不能只靠颜色表达状态，需要图标、文本或结构辅助
- 对大动效、滚动动画要尊重 prefers-reduced-motion
- 面试中不要只停留在「对比度、高对比模式与 reduced motion」的定义，还要解释为什么需要它、它解决了哪类问题，以及在哪些约束下会失效。

#### 工程化补充

- 场景前提：回答 对比度、高对比模式与 reduced motion 时先锁定 视觉可访问性 的边界条件，避免把经验结论当成通用规则。
- 实施步骤：先说触发条件，再解释机制，再给反例，避免把“结果”当成“原因”，并且动作安排要覆盖主路径和异常路径，确保上线后可追踪可纠偏。
- 失败风险：常见风险是只给理想路径，忽略 视觉可访问性 的失败分支与恢复动作。
- 验收信号：验收至少包含围绕 视觉可访问性 的可复现用例、线上监控指标和回退演练记录。

### 代码示例

```css
/* 1. 对比度：正文至少 4.5:1，大字至少 3:1（WCAG AA） */
:root {
  --text: #111; /* 与白底对比度 ~17:1 */
  --text-muted: #666; /* 与白底对比度 ~5.7:1 */
  --link: #0958d9; /* 与白底对比度 ~4.6:1 */
}

/* 2. 不仅靠颜色：状态用颜色 + 图标 + 文字 */
.status-error::before {
  content: '❌ ';
}
.status-success::before {
  content: '✅ ';
}

/* 3. 高对比度模式 */
@media (prefers-contrast: more) {
  :root {
    --text: #000;
    --bg: #fff;
    --border: #000;
  }
  button {
    border: 2px solid currentColor;
  }
}

/* 4. 减少动效（眩晕症友好） */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 5. focus-visible：仅键盘导航显示焦点环 */
button:focus {
  outline: none;
}
button:focus-visible {
  outline: 3px solid #0ea5e9;
  outline-offset: 2px;
}
```

```ts
// JS 端检测用户偏好
const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduceMotion) playEntryAnimation();
```

## vue-i18n-intl

title: Vue I18n、Intl API 与多语言资源组织
followups: [vue-i18n-intl-followup-1, vue-i18n-intl-followup-2, vue-i18n-intl-followup-3]
difficulty: 进阶
tags: [i18n, Intl]

### 一句话

这题的高分关键是把 i18n 讲成可执行方案：前提清晰、步骤可落地、验收可验证。

### 题目

国际化为什么不只是“把文案抽出去”？日期、数字、复数规则又该如何处理？

### 答案要点

- 文案资源需要命名规范、按页面/领域拆分、支持懒加载
- 日期、数字、货币、相对时间应尽量使用 Intl 系列 API
- 复数规则、占位顺序、语序变化不能硬编码中文思维
- 面试中不要只停留在「Vue I18n、Intl API 与多语言资源组织」的定义，还要解释为什么需要它、它解决了哪类问题，以及在哪些约束下会失效。

#### 工程化补充

- 场景前提：讨论 Vue I18n、Intl API 与多语言资源组织 时要交代响应式依赖怎么收集、何时触发更新、如何清理副作用。
- 实施步骤：先说触发条件，再解释机制，再给反例，避免把“结果”当成“原因”，并且动作要交代响应式依赖和组件更新时机，避免副作用漂移。
- 失败风险：常见风险是响应式边界不清导致连锁重渲染和状态抖动。
- 验收信号：验收至少看组件重渲染次数、关键交互耗时和状态一致性。

### 代码示例

```ts
// 1. Vue I18n 9：按语言/页面拆分 + 懒加载
import { createI18n } from 'vue-i18n';

const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en',
  messages: {},
});

async function loadLocale(locale: string) {
  const messages = await import(`@/locales/${locale}.json`);
  i18n.global.setLocaleMessage(locale, messages.default);
  i18n.global.locale.value = locale as any;
  document.documentElement.lang = locale;
}
```

```vue
<template>
  <!-- 2. 模板里使用 -->

  <!-- 3. 复数（注意不同语言的规则不同）-->
  <p>{{ $t('cart.items', { count }, count) }}</p>

  <!-- 4. 占位符顺序由翻译者控制 -->
  <p>{{ $t('greeting', { name: user.name, date }) }}</p>
</template>
```

## i18n-async-locale-routing

title: 多语言资源拆分与按路由懒加载

difficulty: 资深
tags: [i18n, 异步, vue-i18n, 高频]

### 一句话

这题回答要覆盖 i18n 的适用前提、实现路径和异常处理，避免只背定义。

### 题目

你们 i18n 多语言资源是怎么拆分和运行时切换的？切路由时异步语言包加载时机是怎么处理的？资源加载完全依赖 vue-i18n 还是有自己的策略？

### 答案要点

- 按 locale（zh-CN / en-US / ja-JP）肯定拆
- 再按 模块 / 路由（home / order / settings）二级拆
- 命名：locales/{locale}/{module}.json
- 公共部分：common / errors / global，启动时拉

#### 工程化补充

- 场景前提：先划清 i18n 的作用域和更新时机，再展开 多语言资源拆分与按路由懒加载，避免状态边界混乱。
- 实施步骤：先把 i18n 拆成可执行子步骤，再逐步落地并记录每一步的输入输出，并且动作要交代响应式依赖和组件更新时机，避免副作用漂移。
- 失败风险：常见风险是响应式边界不清导致连锁重渲染和状态抖动。
- 验收信号：验收至少看组件重渲染次数、关键交互耗时和状态一致性。

### 代码示例

```ts
import { createI18n } from 'vue-i18n';

export const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en-US',
  messages: {},
});

const localeModules = import.meta.glob('../locales/**/*.json');

const loaded = new Set<string>();

export async function loadNs(locale: string, ns: string) {
  const key = `${locale}:${ns}`;
  if (loaded.has(key)) return;
  const path = `../locales/${locale}/${ns}.json`;
  const loader = localeModules[path];
  if (!loader) return;
  const mod = (await loader()) as { default: Record<string, unknown> };
  i18n.global.mergeLocaleMessage(locale, { [ns]: mod.default });
  loaded.add(key);
}

export async function switchLocale(target: string) {
  const reload = Array.from(loaded)
    .map((k) => k.split(':'))
    .filter(([loc]) => loc !== target)
    .map(([, ns]) => loadNs(target, ns));
  await Promise.all(reload);
  i18n.global.locale.value = target;
  document.documentElement.lang = target;
}

router.beforeEach(async (to) => {
  const ns = to.meta?.i18nNs as string | undefined;
  if (ns) await loadNs(i18n.global.locale.value, ns);
});
```

### 常见误区

- 把所有语言一次全 import：bundle 翻 N 倍
- 路由切换时不 await 语言包：用户先看到 key（如 `home.title`）
- 只换 i18n locale 不换 html lang：a11y / 字体回退异常
- 切换语言时清空已加载缓存：用户来回切，反复请求

### 追问

- vue-i18n 还是自己写，怎么选？
  - 简单业务用 vue-i18n；复杂格式（plural / context）/ 多端复用考虑 i18next + ICU MessageFormat
- 切路由时语言包加载失败怎么办？
  - fallback locale + UI 容错（不阻塞渲染，先用 key + 后台重试）
- 服务端渲染时怎么协调？
  - SSR 一开始注入页面用到的全部 ns，client hydrate 时已包含；客户端切换继续懒加载

### 延伸

- 进阶：把语言包接入 CDN + ETag，浏览器/CDN 双缓存
- 工程：CI 跑一致性脚本，确保 zh / en / ja 之间 key 一致；缺失 key 自动报警
