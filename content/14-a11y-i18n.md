## wcag-semantic

title: 可访问性的起点是语义化，而不是补 ARIA
followups: [wcag-semantic-followup-1, wcag-semantic-followup-2, wcag-semantic-followup-3]
links: [04-css/native-popover-dialog-anchor, a11y-quick-wins-basic, aria-roles-states]
difficulty: 基础
tags: [a11y, 语义化]

### 一句话

语义元素自带角色、键盘行为和可访问树信息；用按钮就用 <button>，不要拿 <div> 模拟点击；表单关联 label、标题层级、列表结构、表格语义都是基础。

### 题目

为什么说“先用对 HTML 元素，再谈 ARIA”？请举几个典型例子。

### 答案要点

- 语义元素自带角色、键盘行为和可访问树信息
- 用按钮就用 `<button>`，不要拿 `<div>` 模拟点击
- 表单关联 `label`、标题层级、列表结构、表格语义都是基础
- ARIA 主要用于补充原生语义不足，而不是替代原生语义

#### 补充说明

- 面试中不要只停留在「可访问性的起点是语义化，而不是补 ARIA」的定义，还要解释为什么需要它、它解决了哪类问题，以及在哪些约束下会失效。
- 可以围绕 a11y、语义化 展开：先给核心机制，再补工程场景，最后说明替代方案和取舍理由。
- 回答时要从定义、机制、边界、落地和验证五个层面展开。
- 落地时建议给出验证路径：单测覆盖边界，集成测试覆盖主链路，线上通过日志、指标或灰度观察真实效果。
- 如果答案涉及兼容性、性能或安全，要主动说明默认方案、例外场景和回滚策略。

### 代码示例

```html
<!-- ❌ 反例：div 模拟按钮，丢失键盘可访问性 -->
<div class="btn" onclick="submit()">提交</div>

<!-- ✅ 用原生 button -->
<button type="button" @click="submit">提交</button>

<!-- ✅ 表单：label 关联 input，错误用 aria-describedby -->
<label for="email">邮箱</label>
<input
  id="email"
  v-model="email"
  type="email"
  required
  aria-invalid="true"
  aria-describedby="email-err"
/>
<p id="email-err" class="error">请填写有效邮箱</p>

<!-- ✅ 标题层级：h1→h2→h3 不要跳级 -->
<main>
  <h1>页面标题</h1>
  <section>
    <h2>章节标题</h2>
    <h3>子标题</h3>
  </section>
</main>

<!-- ✅ 图片必须有替代文本（装饰性图片用空 alt） -->
<img src="logo.svg" alt="公司 Logo" />
<img src="bg.svg" alt="" role="presentation" />

<!-- ✅ 列表用 ul/ol/li，表格用 table/th/td/caption -->
<table>
  <caption>
    2026 销售数据
  </caption>
  <thead>
    <tr>
      <th scope="col">月份</th>
      <th scope="col">销量</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">1月</th>
      <td>120</td>
    </tr>
  </tbody>
</table>
```

## focus-keyboard

title: 键盘导航与焦点管理是前端最常见的无障碍硬指标
followups: [focus-keyboard-followup-1, focus-keyboard-followup-2, focus-keyboard-followup-3]
links: [04-css/native-popover-dialog-anchor, a11y-quick-wins-basic, aria-roles-states]
difficulty: 进阶
tags: [焦点管理, 键盘]

### 一句话

打开弹窗时应把焦点移入，关闭时归还触发元素；模态框内要做焦点圈闭，避免 Tab 跑到背景页面；键盘操作应支持 Esc 关闭、方向键切换、Enter/Space 激活等。

### 题目

做弹窗、抽屉、下拉菜单时，焦点管理为什么经常决定可访问性成败？

### 答案要点

- 打开弹窗时应把焦点**移入**到首个可交互元素，关闭时**归还**触发它的按钮
- 模态框内要做**焦点圈闭（focus trap）**，避免 Tab 跑到背景页面
- 键盘操作应支持 **Esc 关闭、方向键切换、Enter/Space 激活、Tab 顺序合理**
- 隐藏元素用 `inert` 或 `aria-hidden="true"`，避免读屏器读到背景内容
- 自定义组件（dropdown / tabs）必须遵循 [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) 的键盘交互模式
- 测试：用键盘从头到尾走一遍流程，再用 NVDA / VoiceOver 听一遍

### 代码示例

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';

const props = defineProps<{ open: boolean }>();
const emit = defineEmits<{ (e: 'close'): void }>();

const dialogRef = ref<HTMLDivElement>();
let lastActive: HTMLElement | null = null;

watch(
  () => props.open,
  async (open) => {
    if (open) {
      lastActive = document.activeElement as HTMLElement;
      await nextTick();
      // 1. 焦点移入弹窗第一个可聚焦元素
      const first = dialogRef.value?.querySelector<HTMLElement>(
        'input,button,select,textarea,[tabindex]:not([tabindex="-1"])',
      );
      first?.focus();
    } else {
      // 2. 关闭后焦点归还触发元素
      lastActive?.focus();
    }
  },
);

// 3. 焦点圈闭：Tab/Shift+Tab 不能跳出弹窗
function onKeydown(e: KeyboardEvent) {
  if (!props.open) return;
  if (e.key === 'Escape') return emit('close');
  if (e.key !== 'Tab') return;

  const focusables = dialogRef.value!.querySelectorAll<HTMLElement>(
    'input,button,select,textarea,a[href],[tabindex]:not([tabindex="-1"])',
  );
  const first = focusables[0];
  const last = focusables[focusables.length - 1];

  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }
}

window.addEventListener('keydown', onKeydown);
onUnmounted(() => window.removeEventListener('keydown', onKeydown));
</script>

<template>
  <Teleport to="body">
    <div v-if="open" ref="dialogRef" role="dialog" aria-modal="true" aria-labelledby="dialog-title">
      <h2 id="dialog-title">确认操作</h2>
      <button @click="$emit('close')" aria-label="关闭对话框">×</button>
      <slot />
    </div>
  </Teleport>
</template>
```

## aria-live-errors

title: aria-live、错误提示与动态内容更新
followups: [aria-live-errors-followup-1, aria-live-errors-followup-2, aria-live-errors-followup-3]
difficulty: 进阶
tags: [ARIA, 表单]

### 一句话

### 题目

动态提示、表单报错、加载状态要怎样做，屏幕阅读器才能感知？

### 代码示例

```vue
<template>
  <!-- 1. 重要状态变更：aria-live="assertive" 立即播报 -->
  <div role="alert" aria-live="assertive">
    <p v-if="error">{{ error }}</p>
  </div>

  <!-- 2. 一般动态信息：aria-live="polite" 等待空闲再播 -->
  <div aria-live="polite" class="sr-only">
    {{ statusMessage }}
  </div>

  <!-- 3. 加载中：aria-busy + 可见文字 -->
  <button :aria-busy="loading" :disabled="loading">
    <span v-if="loading">提交中...</span>
    <span v-else>提交</span>
  </button>

  <!-- 4. 表单错误：aria-describedby 关联 -->
  <label for="pwd">密码</label>
  <input
    id="pwd"
    type="password"
    :aria-invalid="!!errors.pwd"
    aria-describedby="pwd-help pwd-err"
  />
  <p id="pwd-help">至少 8 位，包含字母与数字</p>
  <p id="pwd-err" v-if="errors.pwd" class="error">{{ errors.pwd }}</p>
</template>

<style>
/* 屏幕阅读器可见但视觉隐藏 */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```

## reduced-motion-contrast

title: 对比度、高对比模式与 reduced motion
followups: [reduced-motion-contrast-followup-1, reduced-motion-contrast-followup-2, reduced-motion-contrast-followup-3]
difficulty: 基础
tags: [视觉可访问性, 动效]

### 一句话

对比度不足会导致正文、按钮和状态信息难以辨认；不能只靠颜色表达状态，需要图标、文本或结构辅助；对大动效、滚动动画要尊重 prefers-reduced-motion。

### 题目

为什么“看起来高级”的设计，可能恰恰会损害可访问性？

### 答案要点

- 对比度不足会导致正文、按钮和状态信息难以辨认

- 面试中不要只停留在「对比度、高对比模式与 reduced motion」的定义，还要解释为什么需要它、它解决了哪类问题，以及在哪些约束下会失效。

### 代码示例

```css
/* 1. 对比度：正文至少 4.5:1，大字至少 3:1（WCAG AA） */
:root {
  --text: #111; /* 与白底对比度 ~17:1 */
  --text-muted: #666; /* 与白底对比度 ~5.7:1 */
  --link: #0958d9; /* 与白底对比度 ~4.6:1 */
}

/* 2. 不仅靠颜色：状态用颜色 + 图标 + 文字 */
.status-error::before {
  content: '❌ ';
}
.status-success::before {
  content: '✅ ';
}

/* 3. 高对比度模式 */
@media (prefers-contrast: more) {
  :root {
    --text: #000;
    --bg: #fff;
    --border: #000;
  }
  button {
    border: 2px solid currentColor;
  }
}

/* 4. 减少动效（眩晕症友好） */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 5. focus-visible：仅键盘导航显示焦点环 */
button:focus {
  outline: none;
}
button:focus-visible {
  outline: 3px solid #0ea5e9;
  outline-offset: 2px;
}
```

```ts
// JS 端检测用户偏好
```

### 代码示例

```ts
// 1. Vue I18n 9：按语言/页面拆分 + 懒加载
import { createI18n } from 'vue-i18n';

const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en',
  messages: {},
});

async function loadLocale(locale: string) {
  const messages = await import(`@/locales/${locale}.json`);
  i18n.global.setLocaleMessage(locale, messages.default);
  i18n.global.locale.value = locale as any;
  document.documentElement.lang = locale;
}
```

## aria-roles-states

title: ARIA 的 role / state / property 是什么，什么时候该用

### 题目

ARIA 的 role / aria-\* 属性分别解决什么问题？典型组件（Tabs / Modal / Combobox）需要哪些标注？

### 答案要点

- `role`：告诉辅助技术"这是一个什么角色"（button / dialog / tab / menu / alert）

  - Tabs：tablist > tab[aria-selected] + tabpanel[aria-labelledby]
  - Combobox：`role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`


## form-accessibility

title: 表单 a11y 完整 checklist
followups: [form-accessibility-followup-1, form-accessibility-followup-2, form-accessibility-followup-3]
links: [10-architecture/component-library, a11y-quick-wins-basic, aria-roles-states]
difficulty: 进阶
tags: [无障碍, 表单, 高频]

### 一句话

**label 必须显式关联 input**（`<label for>` 或包裹）；**错误用 aria-invalid + aria-describedby** 关联到错误文案；原生表单优先用 `required`，自定义控件再补 `aria-required`；提交后焦点回到第一个错误项；屏幕阅读器要能完整朗读"标签 + 当前值 + 错误"。

### 题目

做一个登录表单 / 注册表单怎么保证无障碍？提交校验失败时怎么处理才友好？

### 答案要点

- **基础语义**
  - 用原生 `<form>` `<input>` `<button>`，不要 `<div onclick>` 伪装
  - 每个 input 一个明确的 label，要么 `<label for="email">` 要么把 input 包在 label 里
  - placeholder 不能替代 label：不同读屏器行为不一致，且用户开始输入后提示消失，可见性和可访问名称都不稳定
- **必填 / 类型 / 自动填充**
  - 必填：原生 input 优先用 `required`；自定义控件或复杂组合控件再补 `aria-required="true"`
  - 类型语义化：`type="email" / tel / url / password`，移动端弹合适键盘
  - autocomplete：`autocomplete="email" / current-password / new-password / one-time-code`，省事+安全
- **错误处理**
  - 出错的 input 加 `aria-invalid="true"`
  - 错误文案用唯一 id，input 的 `aria-describedby` 指过去
  - 错误文案也用 `role="alert"` 或在 live region 里更新（屏幕阅读器立刻读出）
  - 提交后用 JS 把焦点移到第一个错误项（用户不用 Tab 找）
- **不仅靠颜色**
  - 红框 + 图标 + 文字三重提示（色盲也能识别）
  - 对比度 ≥ 4.5:1
- **键盘**
  - Tab 顺序符合视觉顺序
  - Enter 提交（除非显式禁用）
  - Esc 关闭弹窗 / 清空（视产品而定）
- **加载与禁用**
  - 提交中：button disabled + 显示 spinner + `aria-busy="true"`
  - 不要禁用整个 form 让用户以为卡死，加文案"提交中..."

### 代码示例

```html
<form @submit.prevent="onSubmit" novalidate>
  <div class="field">
    <label for="email">邮箱</label>
    <input
      id="email"
      v-model="form.email"
      type="email"
      autocomplete="email"
      required
      aria-required="true"
      :aria-invalid="errors.email ? 'true' : 'false'"
      :aria-describedby="errors.email ? 'email-err' : undefined"
    />
    <p v-if="errors.email" id="email-err" class="err" role="alert">{{ errors.email }}</p>
  </div>
```

## a11y-quick-wins-basic

title: 前端无障碍（a11y）最容易拿分的 5 件事
followups: [a11y-quick-wins-basic-followup-1, a11y-quick-wins-basic-followup-2, a11y-quick-wins-basic-followup-3]
links: [04-css/native-popover-dialog-anchor, aria-roles-states, focus-keyboard]
difficulty: 基础
tags: [a11y, 无障碍, 基础]

### 一句话

语义化标签 + 可见焦点 + 替代文本 + 充足对比度 + 表单 label —— 这五件事覆盖大部分 a11y 检查项。

### 题目

列出 5 个前端最容易实现、收益最大的无障碍最佳实践。

### 答案要点

1. **语义化标签**：用 `<button>` 不要 `<div onClick>`；导航用 `<nav>`，主体用 `<main>`，有助屏幕阅读器导航
2. **可见焦点**：不要 `outline: none` 一刀切；可换成 `:focus-visible` 自定义样式
3. **图片 alt**：装饰图 `alt=""`（明确空值），有信息的图描述用途；icon 按钮加 `aria-label`
4. **颜色对比度**：正文 ≥ 4.5:1，大字 ≥ 3:1；不要用纯色区分错误（要 + 文字 / icon）
5. **表单 label**：`<label for="email">` 或 `<label><input/></label>`，否则屏幕阅读器读不到字段名

### 代码示例

```html
<nav>
  <ul>
    <li><a href="/">首页</a></li>
  </ul>
</nav>

<form>
  <label for="email">邮箱</label>
  <input id="email" type="email" required aria-describedby="email-help" />
  <p id="email-help">用于接收订单通知</p>
</form>

<button aria-label="关闭弹窗" class="icon-btn">×</button>

<style>
  :focus-visible {
    outline: 2px solid #0ea5e9;
    outline-offset: 2px;
  }
</style>
```

### 常见误区

- 给 div 加 `role="button"` 但没加 `tabIndex` 和键盘事件 → 不能被键盘聚焦
- placeholder 当 label 用 → 输入后看不见提示，对屏幕阅读器也不友好
- 错误用红色文案不加 icon / 文字 → 色盲用户感知不到

### 追问

- aria-live 区分 polite vs assertive
- 怎么测 a11y（axe-core / Lighthouse / 真机 VoiceOver）
- 跳转链接（skip to content）放在哪里

### 延伸

- WCAG 2.2 新增了 7 条标准，可关注 focus 不被遮挡和拖拽替代
- iOS VoiceOver / macOS VoiceOver 可在浏览器开调试

## i18n-async-locale-routing

title: 多语言资源拆分与按路由懒加载
followups: [i18n-async-locale-routing-followup-1, i18n-async-locale-routing-followup-2, i18n-async-locale-routing-followup-3]
difficulty: 资深
tags: [i18n, 异步, vue-i18n, 高频]

### 一句话

按"语言 × 模块"拆分语言包成独立 chunk；启动只加载当前 locale 的公共部分，路由切换时按需 import 对应模块包；切换语言时把已加载模块重新拉一份目标语言；vue-i18n 9 提供 lazy load 和 setLocaleMessage API，自己实现也很轻。

### 题目

你们 i18n 多语言资源是怎么拆分和运行时切换的？切路由时异步语言包加载时机是怎么处理的？资源加载完全依赖 vue-i18n 还是有自己的策略？

### 答案要点

**拆分维度**

- 按 **locale**（zh-CN / en-US / ja-JP）肯定拆
- 再按 **模块 / 路由**（home / order / settings）二级拆
- 命名：`locales/{locale}/{module}.json`
- 公共部分：common / errors / global，启动时拉

**加载策略（关键）**

- **app start**：只加载 `${currentLocale}/common.json`
- **路由切换**：在 `router.beforeEach` 拦截，拉 `${currentLocale}/${routeMeta.i18nNs}.json`，加载完才 next()
- **language switch**：拉所有"已加载过的模块"的目标语言版本，setLocaleMessage 注入；UI 整体重新渲染（compute property reactive）
- **预取**：在空闲时（rIC）prefetch 用户可能下一步用到的模块语言包

**实现选择**

- vue-i18n 9.x 已经支持 `legacy: false`（Composition API 模式）+ `setLocaleMessage(locale, msg)` 动态注入
- 自家实现也不复杂：维护 `loadedNs: Set<string>` 防重复，用 `import.meta.glob` 动态 import
- 也可以用 i18next + i18next-http-backend，按需远程拉

**避免的坑**

- 切语言时**只切了 i18n** 但 dayjs / number formatter 没切：要联动
- 路由 await 加载语言包卡住 UX：要有 fallback message + skeleton
- 语言包过大：超大 enum 文案应分页 / 按业务路径懒加载
- SSR 必须一开始就加载所有 server 渲染的 namespace

### 代码示例

```ts
import { createI18n } from 'vue-i18n';

export const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en-US',
  messages: {},
});

const localeModules = import.meta.glob('../locales/**/*.json');

const loaded = new Set<string>();

export async function loadNs(locale: string, ns: string) {
  const key = `${locale}:${ns}`;
  if (loaded.has(key)) return;
  const path = `../locales/${locale}/${ns}.json`;
  const loader = localeModules[path];
  if (!loader) return;
  const mod = (await loader()) as { default: Record<string, unknown> };
  i18n.global.mergeLocaleMessage(locale, { [ns]: mod.default });
  loaded.add(key);
}

export async function switchLocale(target: string) {
  const reload = Array.from(loaded)
    .map((k) => k.split(':'))
    .filter(([loc]) => loc !== target)
    .map(([, ns]) => loadNs(target, ns));
  await Promise.all(reload);
  i18n.global.locale.value = target;
  document.documentElement.lang = target;
}

router.beforeEach(async (to) => {
  const ns = to.meta?.i18nNs as string | undefined;
  if (ns) await loadNs(i18n.global.locale.value, ns);
});
```

### 常见误区

- 把所有语言一次全 import：bundle 翻 N 倍
- 路由切换时不 await 语言包：用户先看到 key（如 `home.title`）
- 只换 i18n locale 不换 html lang：a11y / 字体回退异常
- 切换语言时清空已加载缓存：用户来回切，反复请求

### 追问

- vue-i18n 还是自己写，怎么选？
  - 简单业务用 vue-i18n；复杂格式（plural / context）/ 多端复用考虑 i18next + ICU MessageFormat
- 切路由时语言包加载失败怎么办？
  - fallback locale + UI 容错（不阻塞渲染，先用 key + 后台重试）
- 服务端渲染时怎么协调？
  - SSR 一开始注入页面用到的全部 ns，client hydrate 时已包含；客户端切换继续懒加载

### 延伸

- 进阶：把语言包接入 CDN + ETag，浏览器/CDN 双缓存
- 工程：CI 跑一致性脚本，确保 zh / en / ja 之间 key 一致；缺失 key 自动报警

- 放行期间提供补偿措施：替代入口、人工辅助说明、客服兜底路径，降低用户实际伤害。
- 复盘时追踪三类指标：例外数量、逾期回收率、无障碍相关投诉/工单变化。
