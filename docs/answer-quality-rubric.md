# 答案质量标准（主问题 + 追问题）

本标准用于约束 `content/*.md` 的答案改写质量，避免“空泛、重复、模板化”。

## 适用范围

- 主问题：所有题目的 `### 答案要点`
- 追问题：所有 `*-followup-*` 题目的 `### 答案要点`

## 主问题最小要求

每道主问题答案至少满足以下四项：

1. **场景前提**：明确回答适用的业务上下文、输入约束或环境边界。
2. **可执行步骤**：给出可落地的实现/排查/决策步骤，而不是只给概念定义。
3. **失败风险**：包含至少一个失败模式、误用风险或反例。
4. **验证信号**：提供可复核的指标、日志、测试或验收口径。

## 追问题最小要求

在满足主问题四项基础上，追问题还需满足：

1. **直接回应追问意图**：必须对追问本身作答，不能复读父题定义。
2. **动作化回答**：至少包含一个可执行动作（如排查、灰度、回滚、验收）。
3. **父题差异化**：与父题答案保持明显差异，避免“换壳复述”。

## 禁用写法（命中即需重写）

- 无对象空话：例如“主链路/异常链路/长期维护成本更高”但没有具体对象。
- 机械流程口号：固定模板流程反复出现且不含题目特异信息。
- 截断句：如“如果指标没有改善。”这类未闭合、不可执行句子。
- 追问复读父题：追问答案与父题答案高度重合，仅换词不换信息。

## 推荐回答结构

### 主问题

- 结论（20-40 秒可讲清）
- 机制与步骤（按工程顺序）
- 边界与失败场景（至少 1 个）
- 验证与验收（指标/日志/测试）

### 追问题

- 直答（先正面回应追问）
- 关键动作（2-4 条可执行步骤）
- 风险与回退（失败时怎么做）
- 验收信号（如何证明回答成立）

## 验收方式

- 结构一致性：`pnpm validate:content`
- 质量规则：脚本检测模板化短语、追问复读、截断句和动作缺失
- 全量回归：`pnpm build`
